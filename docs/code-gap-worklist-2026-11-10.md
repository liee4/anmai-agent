# 比赛原型代码缺口处理顺序

更新日期：2026-11-10。以 [赛事要求对照](../presentation/赛事要求对照与代码差距.md) 为准；这里记录逐项处理结果，避免把工程功能与真实医疗验证混为一谈。

1. **公开真实数据接入：已完成单记录首步。** BIDMC `bidmc_01` 原始数值文件纳入仓库并校验哈希；35 秒回放在页面展示来源、许可和缺测，走现有规则判断，不进入个人基线。其他公开数据集尚未接入。[数据说明](../apps/api/data/README.md)
2. **行业知识层：已完成可追溯首步。** 3 条官方来源摘要版本化，相关条目进入普通异常模型复核，页面展示来源。仍需临床专家审核、维护与扩充。[知识层说明](knowledge/evidence-library.md)
3. **临床校准：已提供离线评估接口，尚不能完成校准。** `pnpm eval:windows <本地 JSON>` 可计算有标签窗口的规则层灵敏度/特异度；用户确认目前没有可用的去标识化、已标注目标人群数据。BIDMC 无相应事件标签，不能代替。[评估接口](validation/offline-evaluation.md)
4. **真实通知、急救与设备连接：第一版仍为模拟。** 需要确定目标设备、授权联系人与发送渠道，并与急救机构建立实际接入流程；当前不触发真实拨号或发送。
5. **受控文字回复：已加入；语音识别仍未加入。** 佩戴者可输入简短文字，系统仅给出“需要亲属／我没事／无法确定”的建议；只有再次确认后才调用原有状态机。歧义回复不自动推进。该入口采用保守的代码词句匹配，不能当成通用自然语言医疗理解。原有按钮保留。
6. **Railway 公开网址：目前按用户节省额度的要求暂停。** 本地新版本已验证，比赛前需更新并恢复部署，再核对公开链接与现场 DeepSeek Key 配置。

第 1、2、5 项的新增代码有自动测试与浏览器流程测试。第 3 项只提供评估工具，未给出任何临床性能数字。第 4、6 项均未完成真实部署或第三方接入。
