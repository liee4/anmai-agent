# 比赛原型代码缺口处理顺序

更新日期：2026-11-10。以 [赛事要求对照](../presentation/赛事要求对照与代码差距.md) 为准；这里记录逐项处理结果，避免把工程功能与真实医疗验证混为一谈。

1. **公开真实数据接入：已完成同一数据集的三条记录。** BIDMC `bidmc_01` 展示平稳和缺测，`bidmc_21`、`bidmc_32` 用原始测量值分别演示高心率和低血氧触发固定边界。35 秒回放显示来源和许可，不进入个人基线；其他公开数据集尚未接入。[数据说明](../apps/api/data/README.md)
2. **行业知识层：已完成可追溯首步。** 3 条官方来源摘要版本化，相关条目进入普通异常模型复核，页面展示来源。仍需临床专家审核、维护与扩充。[知识层说明](knowledge/evidence-library.md)
3. **临床校准：已提供离线评估接口，尚不能完成校准。** `pnpm eval:windows <本地 JSON>` 可计算有标签窗口的规则层灵敏度/特异度；用户确认目前没有可用的去标识化、已标注目标人群数据。BIDMC 无相应事件标签，不能代替。[评估接口](validation/offline-evaluation.md)
4. **真实通知、急救与设备连接：第一版仍为模拟。** 需要确定目标设备、授权联系人与发送渠道，并与急救机构建立实际接入流程；当前不触发真实拨号或发送。
5. **受控文字回复：已加入；语音识别仍未加入。** 佩戴者可输入简短文字，系统仅给出“需要亲属／我没事／无法确定”的建议；只有再次确认后才调用原有状态机。歧义回复不自动推进。公开演示的 DeepSeek 模式会调用模型理解文字，Fake 模式使用本地词句规则；模型失败时回退到本地规则，页面标明实际来源。规则能识别“心脏有点疼”等明显不适并覆盖模型错误的安全结论；目前仍不是经临床验证的医疗语言理解。原有按钮保留。
6. **Railway 公开网址：本轮部署待排查。** GitHub `main` 已同步文字理解改动，但用户报告 Railway 部署存在问题；当前不把线上版本视作已更新。待部署问题解决后，核对实际运行提交、评委 `/join/<DEMO_ACCESS_TOKEN>` 入口和现场 DeepSeek 模式。
7. **活动状态自动识别：后续优化，当前不改实时规则。** 目前实时输入依赖外部提供 `resting`／`activity`／`night` 标记；BIDMC 无活动字段，按 `unknown` 处理，不使用个人基线软阈值。接入实际设备时，增加加速度或步数与体征的时间对齐、活动状态及置信度判断，并分别验证静息和活动基线。活动状态无法确定时，应明确展示“判断受限”，通过佩戴者确认补充信息；固定安全边界仍独立生效。基线学习仅纳入活动状态可信的数据。不得仅凭心率升高倒推佩戴者正在运动，也不得给 BIDMC 原始记录补造活动标签。

第 1、2、5 项的新增代码有自动测试与浏览器流程测试。第 3 项只提供评估工具，未给出任何临床性能数字。第 4 项仍未完成真实设备与第三方急救接入。
