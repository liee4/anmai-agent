# 本地演示操作

## 准备

在 `anmai` 目录运行 `pnpm install`、`pnpm verify`、`pnpm dev`。打开 `http://127.0.0.1:5173`。默认使用离线 Fake Provider，能稳定演示完整流程。需要真实 DeepSeek 生成时，先在 API 进程环境设置 `BASELINE_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY`；不要把密钥放进演示页面或仓库。

现场展示真实 DeepSeek 调用时，在**新的 PowerShell 窗口**进入 `anmai`，执行：

```powershell
$env:BASELINE_PROVIDER = 'deepseek'
$env:DEEPSEEK_API_KEY = Read-Host '请输入 DeepSeek API Key'
$env:DATABASE_PATH = 'data/deepseek-demo.sqlite'
pnpm dev
```

密钥仅存在于该终端启动的进程环境中。`DATABASE_PATH` 使用新的本地文件，是为了避免先前演示已处理过相同的 14 天周期而跳过模型调用。首次导入后，界面应显示 Provider 为 `deepseek` 且基线版本为 `v1`；这表示本次使用配置的密钥取得了通过校验的模型结果。若仍无基线版本，说明模型请求或候选校验未成功；不要声称演示已生成基线。演示前请用自己的密钥完整试跑一次，API 用量由 DeepSeek 账户计费。

## 场景一：基线

点击“填入下一轮 14 天数据”与“导入并检查基线”。观察历史模式、14 天覆盖、有效日、完整周期和基线版本。个人基线卡显示本地统计的观察值与 Provider 名。每次导入后再次填入，会得到下一周期且体征数值有所变化；再次导入同一批 JSON 不会重复生成版本。

## 场景二：佩戴者表示无事

点击“持续异常”，在倒计时内点击“我没事”。事件关闭，卡片显示后台继续监测和一次复查时间。再次点击“持续异常”不会立即重新询问；点击“明显恶化”会创建新事件并进入主要亲属阶段。

## 场景三：佩戴者不舒服

先结束上一事件，重新点击“持续异常”和“我不舒服，需要亲属”。基线学习状态变为暂停。主要亲属可点击“亲属已接管”；或者点击“无法接管”转到其他亲属。其他亲属也未接管时进入模拟接线端，屏幕显示位置和播报文本，可手动重播语音。整个过程不拨打真实急救电话。

## 恢复与复位

亲属接管或模拟呼救结束后点击“结束事件”。佩戴者确认恢复时，再点击“我已恢复，重新开启基线学习”。演示计时只能在没有活跃事件时修改。

若要从第一轮重新测试，在“统一数据输入”中点击“重置测试数据”并确认。此操作会清空 `demo-wearer` 的导入体征、每日统计、历史与当前基线、排除记录、监测状态和应急事件；下次“填入下一轮 14 天数据”重新从 2026-10-01 开始，成功生成的基线版本从 v1 计起。其他佩戴者的数据不受影响。SQLite 文件本身仍保留，演示计时设置也不改变。

## 检查点

- `pnpm verify` 覆盖单元与 API 集成测试、TypeScript 检查、生产构建。
- `/api/health` 应返回 `demoOnly: true`。
- 页面刷新后活跃事件和剩余倒计时仍出现；API 使用同一 SQLite 文件重启后，过期计时会继续推进且模拟通知不会重复创建。
