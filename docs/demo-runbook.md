# 本地演示操作

## 准备

在 `anmai` 目录运行 `pnpm install`、`pnpm verify`、`pnpm dev`。打开 `http://127.0.0.1:5173`。默认使用离线 Fake Provider，能稳定演示完整流程。需要真实 DeepSeek 生成时，先在 API 进程环境设置 `BASELINE_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY`；不要把密钥放进演示页面或仓库。

## 场景一：基线

点击“填入 14 天演示数据”与“导入并检查基线”。观察历史模式、14 天覆盖、有效日、完整周期和基线版本。个人基线卡显示本地统计的观察值与 Provider 名。再次导入同一批数据不会重复生成版本。

## 场景二：佩戴者表示无事

点击“持续异常”，在倒计时内点击“我没事”。事件关闭，卡片显示后台继续监测和一次复查时间。再次点击“持续异常”不会立即重新询问；点击“明显恶化”会创建新事件并进入主要亲属阶段。

## 场景三：佩戴者不舒服

先结束上一事件，重新点击“持续异常”和“我不舒服，需要亲属”。基线学习状态变为暂停。主要亲属可点击“亲属已接管”；或者点击“无法接管”转到其他亲属。其他亲属也未接管时进入模拟接线端，屏幕显示位置和播报文本，可手动重播语音。整个过程不拨打真实急救电话。

## 恢复与复位

亲属接管或模拟呼救结束后点击“结束事件”。佩戴者确认恢复时，再点击“我已恢复，重新开启基线学习”。演示计时只能在没有活跃事件时修改。SQLite 数据默认保存在 `apps/api/data/anmai.sqlite`；若需要全新演示，可在服务完全停止后，改用另一个 `DATABASE_PATH` 指向新的本地文件。

## 检查点

- `pnpm verify` 覆盖单元与 API 集成测试、TypeScript 检查、生产构建。
- `/api/health` 应返回 `demoOnly: true`。
- 页面刷新后活跃事件和剩余倒计时仍出现；API 使用同一 SQLite 文件重启后，过期计时会继续推进且模拟通知不会重复创建。
