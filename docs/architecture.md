# 安脉 Agent 第一版架构

## 运行边界

浏览器只通过 `/api` 访问本地 Fastify 服务。API 使用 SQLite 保存导入样本、日总结、基线版本、佩戴者确认指纹、事件、截止时间和模拟通知。数据库迁移在启动时执行。SSE 推送变化，页面也会轮询恢复当前状态。

外部只有一个数据输入口 `POST /api/ingest`。内部 `InputClassifier` 识别逐日或历史数据，再由两个 Adapter 将数据交给相同的归一化、去重、质量检查和日总结流程。逐日输入本地累计；历史输入按天拆分。够一个合格的 14 天周期才生成基线。

首次基线前，导入数据只按固定安全边界排除急性异常，保留可用于个性化学习的长期非急性偏高情况。已有基线后，导入链回放连续样本并用当前个人基线识别持续软异常，记录与实时链相同的样本风险审计及基线排除原因；历史回放不创建实时应急事件。一次导入的保存和审计在同一数据库事务中完成。

## 两条工作循环

**基线循环：** 合格日数据 → 14 天周期 → 代码计算观察基线和可用证据 → 组装最新周期、近期版本、长期摘要的加权记忆包 → `BaselineModelProvider` 提出软阈值和文字规律 → 代码安全校验 → 最多五次生成与反馈 → 发布版本。默认 Fake Provider 可离线演示；设置后可实时调用 DeepSeek。Provider 不读 SQLite，也不决定急救动作。被替换的版本有保留期限，到期后清理其完整数据与模型尝试记录。

**响应循环：** 模拟体征 → `RiskDetector` 进行质量检查、稳定值、持续性和阈值判断 → 普通异常由 `RiskReviewService` 调用有边界的模型复核一次 → `AnmaiAgent` 观察结果并调用受控工具 → `EmergencyService` 在事务中推进状态并保存截止时间 → Agent 读取更新后的事件。明显恶化和佩戴者主动求助不等待模型。佩戴者回应、主要亲属、其他亲属和模拟呼救均由确定性状态机管理。模型生成的文本没有状态转换权限。

普通异常复核前，`knowledgeForRisk` 按风险原因从版本化解释条目中选取相关来源，连同体征证据发送给模型；仪表盘展示相同条目的出处。条目目前是来源已核对、待临床审核的摘要，只辅助说明症状询问和测量局限，不提供阈值或状态转换参数。完整目录通过 `GET /api/knowledge` 查看；没有症状输入时，卒中识别条目不会根据心率或血氧自动匹配。

`POST /api/public-data/bidmc/01/replay` 可读取仓库内已校验哈希的 BIDMC 原始逐秒数值，选取 35 秒窗口映射到演示时间运行现有规则。回放保留原始相对秒数、数据集版本、记录号和许可；未采集的活动、血压、位置不补造，数据不进入基线学习。来源和许可见 [BIDMC 数据说明](../apps/api/data/README.md)。

Agent 工具注册表对输入 Schema 和操作许可做检查。当前主要工具为 `evaluate_risk`、`create_alert`、`record_response` 和 `run_deadlines`。Agent 的调用轨迹可在接口响应中查看，用于演示“观察 → 评估 → 决策 → 执行 → 再观察”。

## 安全与持久化

- 固定阈值是独立的演示参数，个人软阈值不能越过固定边界。
- 新事件保存创建时的基线版本、完整基线快照和计时配置；活跃事件不随之后发布的新基线改变。
- 佩戴者选择“我没事”后关闭事件，持久化异常指纹。同级异常只复查一次；正常持续 60 秒后清除；明显恶化立即重新升级。
- 佩戴者选择“不舒服”后暂停基线学习，事件结束不自动恢复。
- 截止时间、事件版本和模拟通知幂等键保存于 SQLite，重启后可继续执行；旧页面提交过时 `stateVersion` 不会覆盖新状态。
- 亲属通知和急救接线端均为本地模拟，不会发送真实消息或拨打电话。
