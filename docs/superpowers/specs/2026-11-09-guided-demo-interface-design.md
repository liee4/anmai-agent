# 安脉单线引导演示界面设计

状态：用户确认按 `patient-scenarios-v5.html` 草图实施（2026-11-09）。

## 目标

评委能在现场讲解和独立访问两种情况下，看懂一次模拟体征从个人基线、规则判断、模型复核、询问佩戴者到亲属接管或模拟呼救的过程。界面克制、易读，所有状态来自真实后端，不以静态草图状态冒充运行结果。

## 页面结构

1. 页首显示「安脉」标识、用途、模拟性质和 Fake/DeepSeek 模型切换。
2. 「选择患者情景」固定可见：个人基线、正常静息、正常活动、异常有回应、异常无回应、明显恶化、设备松动。点击后调用现有模拟 API；进行中的事件需要先结束或重置，不能虚构场景切换结果。
3. 基线栏固定可见：当前版本、最新 14 天周期、静息/活动心率与血氧中位数、上轮对比、实际证据权重、继续导入下一轮、暂停/恢复、重置演示数据。首轮与后续轮次的模拟体征和日期不同。重置需要确认，清空当前演示佩戴者数据、基线和事件，并从首轮开始；不改变模型模式。
4. 四步横向流程：建立个人基线 → 输入实时体征 → 判断并询问佩戴者 → 联系亲属或模拟呼救。当前步骤由后端状态确定；质量不可信、规则未判异常、模型观察、提醒倒计时、亲属接管和呼救各有清晰文字反馈。
5. 主区只突出当前可执行动作和判断依据。右侧「系统正在做什么」说明接收、规则、模型、佩戴者、亲属链路，显示当前状态与倒计时。
6. 原始 JSON 输入、演示时间设置、事件卡、联系送达和时间线保留在展开区，评委可自行验证。急救和亲属动作均为模拟。

## 数据与真实行为

- 14 天数据由现有 `/api/simulator/history/next` 取得后导入 `/api/ingest`；新版是否发布、版本号和体征统计以返回结果及 dashboard 为准。数据不足、被排除、模型候选不变或校验失败时显示实际原因，不预增版本。
- 模拟数据生成器不应每 5 轮重复同一组体征值。每轮日期不重叠、体征统计有可见差异，同时保持低风险老年人的合理演示范围。
- dashboard 提供当前与上一版仍保留的基线，用于对比；历史过期和排除规则继续由后端执行。界面按后端 `evidenceWeights` 显示 100%、70/30 或 60/30/10。
- 普通异常由规则进入模型复核，观察结束且异常仍在时询问；佩戴者可主动表示不舒服。明显恶化按既有安全规则立即通知亲属。无回应按配置的等待时间升级。
- 佩戴者不舒服后暂停基线学习；事件结束且佩戴者本人确认恢复后才能重启。
- 页面不显示假造的实时体征、模型解释或联系结果。模型不可用、断网、数据不可信时给出明确反馈。

## 验收

桌面与手机均能完成首轮及多轮基线、重置、七种情景、普通异常观察与主动求助、无回应升级、明显恶化与模拟呼救；Fake/DeepSeek 切换和高级 JSON 输入保持可用。自动化浏览器测试覆盖主要路径，`pnpm verify` 通过。仅在本地验证后同步 GitHub；Railway 当前暂停，不自动重新部署。
