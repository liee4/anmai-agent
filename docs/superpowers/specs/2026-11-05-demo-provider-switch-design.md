# 评委公开演示与模型切换设计

## 目的

评委打开稳定的 HTTPS 链接，在安脉页面点击一次，即可让该浏览器之后的基线生成、普通异常复核和事件文案使用 DeepSeek；也能切回 Fake。DeepSeek API Key 保存在托管平台的后端密钥变量中。

## 已选方案与取舍

- **稳定托管链接（采用）**：将前端静态文件和 Node API 放在同一个服务与域名下，使用 Railway 提供的 HTTPS 域名和持久化卷保存 SQLite。Railway 可从 GitHub 部署，配置环境变量与持久化卷；可能产生订阅及资源费用。部署到用户自己的 Railway 账户。
- 本机临时隧道无需托管费用，但链接会变且电脑必须保持运行，当前不采用。
- 通过启动命令切换模型要重启 API，评委现场不方便，当前不采用。

## Key 与公开访问

1. 在 Railway 服务的 Variables 中设置 `DEEPSEEK_API_KEY`；Key 不进入 GitHub、前端代码、浏览器存储、分享 URL 或 API 响应。页面只显示后端是否已配置。
2. 公开链接会包含一个随机演示访问凭证。后端验证后建立演示会话并跳转到不含凭证的页面，评委无需另外输入密码。凭证不是 DeepSeek Key。
3. 每个浏览器会话拥有独立的模拟佩戴者 ID、基线、风险复核和应急事件；切换模式只作用于该会话。后端限制每个会话及全站的 DeepSeek 调用次数，避免公开链接造成不受控用量。
4. SQLite 位于 Railway 持久化卷。部署重启后模拟数据可恢复，页面模式默认 Fake；已发布基线保留实际 Provider 名。上线前只使用模拟数据。

## 页面切换

1. 页面演示设置显示当前会话的 Fake / DeepSeek 模式、Key 是否已配置，并提供一个切换控件。一次切换同时作用于三个 Provider；之后开始的模型任务按选定模式执行。
2. 现有基线、历史审计、事件状态及截止时间不改写。每次生成结果记录实际调用的 Provider。
3. 本会话有正在执行的模型任务、待完成的风险复核或活跃应急事件时，切换返回清楚提示；完成当前流程后重试。其他评委的会话不受影响。
4. 未配置 Key 时不能选 DeepSeek。DeepSeek 调用失败时沿用现有安全回退：普通异常转人工确认，文案使用本地模板，基线候选须经过安全校验。

## 部署步骤

1. 代码提供生产构建及单端口启动配置，服务同时处理页面与 `/api`；监听平台提供的 `PORT` 与公网网卡。
2. 在 Railway 创建服务、连接私有 GitHub 仓库 `liee4/anmai`，设置 `DEEPSEEK_API_KEY`、演示访问凭证、调用上限及 SQLite 路径，挂载持久化卷；生成 Railway HTTPS 域名。
3. 部署后从另一台设备打开评委链接，验证 Fake 与 DeepSeek 切换、基线导入、普通异常与事件流程。密钥和付费资源由用户在其账户里创建与管理。

## 验证

- API 测试覆盖凭证、会话隔离、无 Key 拒绝、在途任务锁定、调用上限、Provider 审计和旧基线保留。
- 浏览器测试覆盖评委链接、页面切换、两个浏览器数据互不干扰；自动测试不消费真实 DeepSeek 额度。
- 上线后人工用用户自己的 Key 试跑一次真实调用，并检查托管平台用量。真实穿戴数据与真实急救通信不在此演示范围。
